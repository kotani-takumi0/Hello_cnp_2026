# H88 8本の分け方を全探索 — 254通り — 2026-08-30

H87 は「アンケートを2段目へ」という**手で選んだ1通り**で負けた。
その1通りが悪かっただけかもしれないので、**8本を2段に分ける254通りすべて**を試した。

**結論: 分けない（現行の加法メタ）が最良。254通り中250通りが探索seedの時点で現行以下。**

再現:

```bash
.venv/bin/python exp/search_cascade_split.py
```

なので2フェーズにした。

| フェーズ | seed | 内容 |
|---|---|---|
| 探索 | 0-4 | 254通り全部。alphaは0.001に固定（速度のため） |
| 検証 | 5,6,7,8,9,42 | 上位6件のみ。**本物の `select_alpha_1se`** で測る |

## 4. H87 との整合

H87 で「アンケートを2段目へ」は ΔAP **-0.0063 (1/11)** だったが、
ここでは同じ趣旨の `→ E2` が **+0.00015 (3/6)** ＝ ほぼゼロになっている。矛盾ではない。

**1段目に E7_cross が残っているかどうかが違う。** H87 は E7 の入力が
不満2/不満4 × 財務でアンケート由来なので1段目から外した（＝1段目を完全に
アンケート盲にした）。H88 の `→ E2` は E7 を1段目に残しているので、
1段目はアンケート情報を間接的にまだ見ている。

つまり**1段目からアンケートを抜けば抜くほど悪くなる**という、H87 §4 の収支
（アンケート除去 -0.0225、cascade が戻すのは +0.0162 まで）と同じ向きである。

---

## 5. 結論

「1段目と2段目の最良の組み合わせ」の答えは、**分けないこと**だった。

理由は H87 §5 に書いた通り。対数オッズの加法は「弱い信号が効くのは強い信号が
拮抗した時だけ」を既に実装しており、段に分けることは能力の追加ではなく、
**2段目に回した情報源が帯の外で持っている分を捨てる制約**にしかならない。
254通りの全探索がそれを裏づけた。
