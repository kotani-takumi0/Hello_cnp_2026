# H93 企業概要・組織図に、E4の取りこぼしはあるか — 2026-08-30

**結論: 無い。REJECT。**
9本目として足すと残差AUC 0.512〜0.531（損益分岐 0.55 に届かない）、ΔAP +0.0000。
E4の入力を全次元に差し替えるとF1ガードレール違反で悪化する。

再現:

```bash
.venv/bin/python exp/diagnose_overview_org_ceiling.py --mode add
.venv/bin/python exp/diagnose_overview_org_ceiling.py --mode replace
```

## 1. 動機と、その動機の誤り

EDAの事実として、PC1が説明する割合は **DX展望 95% / 企業概要 24% / 組織図 29%**
（[[dx_text_is_one_dimension]]）。DX展望は1次元で閉じたが、他の2本は多次元なので
まだ取り分があるはず——という筋で着手した。

**この筋は間違っている。** 「テキストとして多次元」と「購入について多次元」は別物で、
測ったのは後者である。

## 2. 9本目として足す（11seed、本番外側fold）

損益分岐は **残差AUC 0.55**（0.60で明確、`h92_material_scope_20260830.md` §9.4）。
参考としてE3_dx_text自身の残差AUCが 0.536 で、それにも届いていない。

単体では 0.665〜0.699 出る。**単体で出て残差で消えるのは、その情報を既に他が
持っているということ**である。

## 3. E4の入力を全次元に差し替える（＝質を上げる形）

E4は `CONCAT_SLUGS = ("org", "overview")` を各512次元に切り詰めて連結している。
Matryoshkaの切り詰めで落ちた分があるなら、全次元に戻せば改善するはず——を測った。

| 構成 | E4単体AUC | ΔAUC | ΔAP | ΔF1 | ΔAP>0 | 判定 |
|---|---:|---:|---:|---:|---:|---|
| base（現行 512x2） | **0.706** | — | — | — | — | — |
| 全次元(6144)に差し替え | 0.699 | -0.0009 | -0.0014 | **-0.0050** | 3/11 | REJECT (F1ガードレール) |
| 全次元・C=0.1 | 0.703 | -0.0010 | -0.0022 | **-0.0050** | 2/11 | REJECT (F1ガードレール) |

**現行の切り詰めの方が強い。** 全次元版と現行E4の相関は **0.973** で、
6144次元は512x2と同じ順位を出している。落ちていたのはノイズだった。

## 4. どこに吸われているのか

企業概要+組織図の全次元予測と、各Expertの相関（seed42）:

| Expert | 相関 |
|---|---:|

| E0b_linear | +0.370 |
| E0_anchor | +0.341 |
| E6_manual | +0.331 |
| E1_finance | +0.300 |
| E7_cross | +0.149 |

E4以外にも E0/E0b/E1/E6 と 0.3 前後で重なる。**この2本のテキストの多次元性が
符号化しているのは業種・規模・事業内容**であり、それは E0/E1 が生の列で持っている。
だから単体では 0.70 まで伸びるのに、合成に対する残差は 0.53 になる。

## 5. 読み方

「PC1の占める割合」は**テキストの分散の話**であって、**ラベルについての情報の話**ではない。
残差AUCで測れば1行で決着する。今後「この列はまだ使い切っていないのでは」という
提案が出たら、作る前にこの測り方を当てること（`--mode add` は11seedで数十秒）。

これで**テキスト3本すべてが閉じた**。DX展望は1次元（[[dx_text_is_one_dimension]]）、
企業概要・組織図は多次元だが、その多次元性は表形式データと重複している。
