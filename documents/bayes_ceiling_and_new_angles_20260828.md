# 校正診断・誤りの所在・LB 0.88 への距離 — 2026-08-28

> **改訂履歴**: 初版は「情報上の天井に達している」と結論したが、その根拠となる
> 自己整合テストに検出力が無いことが判明したため全面改訂した。詳細は §2。
> **「上限に達した」という主張は撤回する。**

## 0. 結論

3つに分ける。

### 0.1 確定していること

- 現本命の予測確率は**よく較正されている**（isotonicをかけるとBrierが悪化する）。
- したがって**決定層（閾値則・F1近似損失・Platt校正）に伸びしろは無い** —
  ただしこれは「現在のランキングを固定した上で」の話である。
  `p` が真なら最良の決定則で取れる期待F1は 0.805〜0.832、実測は 0.828〜0.831。
  閾値則7種とF1近似損失7実装とPlattが全滅したのは、これで説明がつく。
- **残る誤り61件のうち53件は、`0.1<p<0.9` の228行に集中している。**
  確信帯514行の誤りは8件のみ。testの曖昧帯は239行しかない。これは直接測定であり、
  下の検出力の問題とは無関係に成立する。

### 0.2 撤回すること

**「このデータの情報上限に達した」とは言えない。** 初版が根拠にした
「`y ~ Bern(p)` シミュレーションと実測が1σ以内で一致する」というテストは、
較正しか見ていない。較正済みモデルではラベルが周辺的に `Bern(p_i)` の独立列に
なるため、真の確率が `p` であっても、より鋭い `p*` であっても、あらゆる指標の
分布が一致する。**このテストの検出力はゼロに近い**（§2で実証）。

### 0.3 LB 0.88 への距離

現在の誤り61件のうち**20件を直せばF1 0.8825**。つまり必要なのは
「約20〜25社を余分に当てること」であり、全行を動かす施策ではない。

再現コマンド:

```bash
.venv/bin/python exp/diagnose_bayes_ceiling.py --power
```

## 2. 初版の誤りと、その実証

### 2.1 何が間違っていたか

初版は「`y ~ Bern(p)` を600回引いて実測がすべて1σ以内 → `p` は真の確率と区別
できない → 情報上限に達した」と論じた。第2の矢印が誤りである。

較正済みモデルでは、ラベルは周辺的に `y_i ~ Bern(p_i)` で互いに独立になる。
真の確率が `p` でも、より鋭い `p*`（ただし `E[p*|p] = p`）でも、
**`(p, y)` から計算されるあらゆる統計量の分布は完全に一致する**。
よってこのテストは、原理的に「より良いモデルの存在」を検出できない。

### 2.2 実証

logitにガウスノイズを足してランキングを壊し、isotonicで較正だけ戻したモデルを
同じテストにかけた。

| モデル | 実AUC | 実最大F1 | z (auc / ap / f1) |
|---|---:|---:|---|
| 本命 p | 0.9645 | 0.8310 | +0.97 / +0.21 / +0.86 |
| 劣化 sd=0.5 | 0.9671 | 0.8418 | -0.07 / -0.08 / +0.06 |
| 劣化 sd=1.0 | 0.9544 | 0.8043 | +0.00 / -0.05 / -0.11 |
| 劣化 sd=2.0 | 0.9213 | 0.7236 | -0.04 / -0.13 / -0.22 |
| 劣化 sd=4.0 | 0.8234 | 0.5833 | -0.05 / -0.10 / **-0.32** |

**F1を0.583まで落としたモデルが、本命より小さい|z|で通過する。**
テストは較正しか見ていない。

## 3. LB 0.88 の読み方

### 3.1 必要な改善量

現在の誤り61件のうち上位n件を直した場合のOOF F1:

| 直す誤り | F1 |
|---:|---:|
| 10件 | 0.8522 |
| 15件 | 0.8678 |
| **20件** | **0.8825** |
| 25件 | 0.8971 |
| 30件 | 0.9112 |

最も不確実な行から順に解決する場合は、上位60行で 0.8883。

**必要なのは「曖昧な230行のうち50〜60行を追加で当てる」ことであり、
全行に効く特徴量ではない。** これは初版の §1.4 の観察がそのまま活きる。

### 3.2 勝者の呪いの寄与（ただし依拠しない）

Public は 800行の30% = 240行しかない。現本命の予測ラベルを固定して行を
リサンプリングすると:

| 評価集合 | mean | sd | p95 | p99 |
|---|---:|---:|---:|---:|
| Public 240行 | 0.8274 | **0.0316** | 0.8781 | 0.8952 |
| Private 560行 | 0.8280 | 0.0123 | 0.8487 | 0.8582 |

真の実力が全員 F1=0.828 の集団でのPublic最高値の期待値:

| チーム数 | E[max Public] | 実力との差 |
|---:|---:|---:|
| 10 | 0.8751 | +0.047 |
| 20 | 0.8853 | +0.058 |
| 50 | 0.8979 | +0.070 |

**LB 0.88 は、トップが自分たちと同じ実力（真値0.83）である場合と完全に整合する。**

ただしこれを言い訳にしない。理由は2つ。

1. §2の通り、より良いモデルの不在は証明できていない。
2. Public sd 0.0316 は「自分たちのPublic 0.800も同じだけ揺れる」ことを意味する。
   真値が0.83で下振れた可能性も、真値が0.78で上振れた可能性も同程度にある。

**計画上は「0.88は本物」と仮定して動くのが正しい。**

## 4. どこに伸びしろがあるか（測定）

各Expertの単体性能と、曖昧帯（`0.1<p<0.9` の228行）でのAUC。

| Expert | 全体AUC | AP | **曖昧帯AUC** |
|---|---:|---:|---:|
| E0_anchor | 0.9459 | 0.8697 | **0.7328** |
| E0b_linear | 0.9310 | 0.8179 | 0.6920 |
| E7_cross | 0.8747 | 0.6859 | 0.6381 |
| E1_finance | 0.8259 | 0.6246 | 0.5808 |
| E6_manual | 0.8253 | 0.6257 | 0.5699 |
| E3_dx_text | 0.7894 | 0.5063 | 0.5577 |
| E4_org_text | 0.7056 | 0.4142 | 0.5770 |
| E2_survey | 0.6806 | 0.4283 | 0.5725 |

3つのテキストembeddingを直接LRにかけた場合（5fold、C探索あり）:

| 入力 | AUC | AP | 曖昧帯AUC |
|---|---:|---:|---:|
| DX展望 emb 3072次元 | 0.7665 | 0.5103 | 0.5311 |
| 組織図 emb | 0.6596 | 0.3619 | 0.5198 |
| 企業概要 emb | 0.6760 | 0.3552 | 0.5567 |
| **3本連結** | 0.8111 | 0.6073 | **0.5670** |

**構造化データのE0単体が曖昧帯AUC 0.7328 なのに対し、テキスト3本を全部使っても
0.5670 しかない。** 現状テキストは、勝負が決まる場所でほぼ何も貢献していない。

解釈は2通りある。

- (a) テキストに情報が無い
- (b) **850文字の物語を3072次元1本に平均する読み方が、742行の線形モデルには
  荒すぎる**

(b)を支持する材料がある。train row 2（y=0）のDX展望は
「業界屈指の前のめり姿勢」「誰よりも早く・深く・広く」と最大級に強気だが、
ラベルは非購入である。「意欲が高い→買う」という単調な関係ではなく、
**すでに充足している企業は買わない**という非単調・意味依存の構造がある。
これは平均プーリングされたembeddingが最も壊しやすく、
全文を読む推論が最も得意とする種類の構造である。

## 5. 施策候補（改訂）

| 優先 | 施策 | 工数 | 根拠 |
|---|---|---|---|
| **1** | **曖昧帯239行をLLMに全文で読ませる** | 1〜2日 | §4。テキストの曖昧帯AUC 0.567 は「読めていない」に見える。20社当てれば0.88 |
| 2 | 疑似ラベルで n=742→1226 | 半日 | 誤り率0.9%でtest 484行が使える（n軸は未攻略） |
| 3 | 提出2枠の `E[max]` 最適化 | 1時間 | Public sd 0.0316。平均が並び誤りが非相関なら +0.005〜0.012 |
| 4 | 曖昧帯の人力精読 | 1日 | プレゼン賞に直結 |
| 5 | ラベルノイズの除去 | 1時間 | `sample_weight` 実験がログに皆無 |

### 施策1の設計

1. testで `0.1 < p < 0.9` の239社を抽出
2. 各社のドシエ（企業概要・組織図・DX展望の全文＋アンケート11問＋主要財務）を作る
3. **埋め込み近傍でtrainからラベル付き事例をk=20件検索して同梱する**
4. 拡張思考ありのLLMに確率で答えさせる（self-consistency 5回）
5. 曖昧帯の中でのみ `logit(p_final) = logit(p_meta) + λ·logit(p_llm)`、λはA側で決定

**H9との違い**: H9はゼロショットの軸抽出（Make-or-Buy 3軸）で、
ラベル付き事例を文脈に入れた in-context learning は未実施。
またH9は全1542行に適用したため1社あたりのコストを上げられなかった。
239社なら1社あたり100倍のコストをかけられる。

**検証**: strict完全ホールドアウトのB側曖昧帯のみ。in-context事例はA側からのみ引く。

## 6. 閉じた扉

### 6.1 生成過程のリーク — 無し

| 調べたもの | 結果 |
|---|---|
| 企業ID | train 0-741 / test 742-1541 の単純分割。corr(ID, y) = -0.084 |
| 会計恒等式 | 総資産 = 流動資産+固定資産、総資産 = 負債+純資産 が全1542行で丸め誤差1以内 |

### 6.2 テキスト×アンケートの不整合特徴 — 無効

DX展望embedding → 各アンケート列をRidge回帰（全1542行、ラベル不使用）した残差。
そもそもテキストがアンケートを予測できず（corr 最大 0.215）、
残差の曖昧帯AUCは 0.406〜0.530 で元の列の焼き直しだった。
