## 1. H58の追試 — 数値は再現、ベースラインが誤り

| 構成 | doc | 再現 | |
|---|---|---|---|
| finance_ratiosなし(8本) | 0.9573 / 0.8768 / 0.8061 | 0.9573 / 0.8768 / 0.8061 | 完全一致 |
| 既存4本のみ | 0.9578 / 0.8800 / **0.7970** | 0.9587 / 0.8817 / **0.8060** | **不一致** |
| 既存4本+H58(5本) | 0.9587 / 0.8813 / 0.8095 | 0.9587 / 0.8813 / 0.8095 | 完全一致 |

3行中2行が4桁一致。H58の実装もスコアも正しく、ズレるのは**比較対象の4本ベースラインだけ**。

docの中心的な主張は「既存4本だけだとF1が0.8061→0.7970に悪化するが、H58がそれを打ち消して
上乗せする」だった。しかし正しいベースラインでは4本はF1を悪化させない（0.8061→0.8060）。
**打ち消すべき悪化が存在しないので、この相互作用は消える。**

### ベースラインがズレた原因の見当（未確定）

キャッシュ名の衝突が最有力。docの通り `finance_ratio_features.py` にH58を統合すると
`add_finance_ratios` が無条件に5本を返すが、キャッシュタグは `finance_ratios` フラグ
からしか作られないため、4本版と5本版が同じ
`_experts_seed42_ratio_concatemb_crosslr_lin0.03.npz` を共有する。`--no-cache` 無しで
片方を走らせると、もう片方の予測が黙って再利用される。
今回の再実装では `_h58` タグを足して塞いである。

### 正しいベースラインに対するH58の実力（5シード、他条件は完全固定）

| seed | ΔAUC | ΔAP | ΔF1 |
|---|---|---|---|
| 0 | -0.0004 | -0.0016 | +0.0020 |
| 1 | -0.0007 | -0.0019 | -0.0031 |
| 2 | -0.0026 | -0.0062 | +0.0022 |
| 3 | +0.0014 | +0.0043 | +0.0012 |
| 4 | -0.0014 | -0.0041 | -0.0032 |
| **mean** | **-0.0007 (1/5)** | **-0.0019 (1/5)** | **-0.0002 (3/5)** |

docの5シード比較（AP +0.0022 3/5、AUC +0.0009 4/5、F1 +0.0057 5/5）とは符号がほぼ反転。
**H58は中立〜わずかに負。**

なお実装自体は正しい。`無形固定資産変動(ソフトウェア関連)` はtrain/test全1542行が負値、
`減価償却費` は全行正値なので、doc の `.abs()` は `cross_features.py` の符号戻しと等価。

### 統合判断の材料として、相関の測り方に注意

docは既存 `ソフト投資比率_売上` との相関を Pearson -0.4953 とし「基準|r|<0.5をわずかに
クリア」としたが、**Spearman は -0.7359** で大きく外れる。`finance_ratio_features.py` の
docstringが却下根拠に挙げるH3(0.77〜0.85)・H7(0.993)はSpearman表記であり、同じ尺度なら
H58は却下レンジに入る。LightGBMは分位ビンで分割するので、木にとっての重複度はSpearman側。

## 2. Publicの解像度 — 何が測れて何が測れないか

Public上昇の正体を切り分けるため、閾値だけ揃えた提出物を作って比較した。

```
S1 4本      @0.275  正例242
S2 H58込み  @0.335  正例225   ← メンバーの構成（Public 0.8095）
S3 4本      @0.335  正例222   ← H58なし、閾値だけ揃えた（Public 0.7967）

S1 vs S2  差 17行/800     S1 vs S3  差 20行/800     S2 vs S3  差 5行/800
test予測の相関(S2,S3) = 0.99974
```

**S3はH58を1列も含まないのに、S2がS1から動かした17行のうち15行を再現する。**
2構成は実質同一モデルで、提出物が17行違ったのは閾値が正例を17件減らしたため。

### Public の混同行列は既約分数から復元できる

| 提出 | Public F1 | 既約分数 |
|---|---|---|
| S2 H58込み@0.335 | 0.8095238095238095 | 17/21 |
| S3 4本@0.335 | 0.7967479674796748 | 98/123 |
| H58込み@0.397 | 0.7627118644067796 | 45/59 |
| halff1構成 | 0.8000000000000000 | 4/5 |

S2/S3の差5行（正味+3）という制約と突き合わせると、整合する解は1つに絞れる。

```
S2: TP=51  FP+FN=24        S3: TP=49  FP+FN=25
Public上の正例予測数の差 = 3  ← 全体の 225-222=3 と一致
```

S2の正例予測数は最大75件、モデルの正例率28%から逆算して **Publicは800行中せいぜい270行**。
したがって **1行の正誤がF1を約0.006〜0.007動かす。**

### 結論: この盤面でPublic 1回が判定できるのは 0.05 以上の効果だけ

- H58は5行の変更 → Public上2〜3行 → **判定不能**
- 閾値0.335→0.397は18行の変更 → Public上8行 → SD±0.03〜0.04 → **+0.012は判定不能**

実際、正例数とPublic F1の間に単調な関係が無い。

```
204正例 → 0.8000    222正例 → 0.7967    225正例 → 0.8095    207正例 → 0.7627
```

18件差で-0.003、3件差で+0.013。**これがこの評価系のノイズ幅。**

| **cbpe_platt**(新) | — | 0.0254 | **+0.0122** | 11/17 | **0.023** |

### 既存6則は `oof_best` と区別がつかない

先行検証（`_resolve_threshold` docstring、5rep で oof_best が fold_mean/rate/half_f1 に
1/5, 1/5, 0/5 で勝ち）は20repでも支持される。ただし**「食い違ったら構成差を疑う前に
検出力を疑う」**べきことも分かった。20repから5rep分を全通り（15,504通り）抽出すると:

```
fold_mean - oof_best の真値 = +0.0023 (20rep)
  5rep平均が正になる割合   59%
  5rep平均の範囲     [-0.0257, +0.0339]
  「5/5勝ち」が出る割合    0.8%   「0/5」が出る割合 3.0%
```

**同一構成・同一データでも5repなら5/5も0/5も出る。** 構成差の証拠にはならない。

さらに `fold_mean` の優位を「meta_8本 − meta_6本」で測ると過大評価になる。引かれる側の
meta_6本も閾値則で変わるため。

```
meta_8本: fold_mean − oof_best = +0.0023   ← 見たいもの
meta_6本: fold_mean − oof_best = -0.0028   ← fold_meanはmeta_6本を悪くしている
見かけの優位 +0.0052 のうち、半分以上が基準側の悪化ぶん
```

### F1で `fold_mean` と `oof_best` を区別することは不可能

```
mean=+0.00234  std=0.02454
検出力80%に必要なリピート数 = 866    20repの検出限界 = 0.0154（実差の6.6倍）
```

866repは回せない。**この選択は証拠を待つ問題ではなく、別基準で決める問題。**

## 4. 閾値アンサンブルの天井 — argmaxには分散の床がある

`fold_mean`（5メンバー）をブートストラップで300メンバーに増やした `boot_mean` を実装した
が、**分散は下がらなかった**（0.0383 → 0.0397）。

```
                oof_best  fold_mean  boot_mean  rule_mean │ cbpe_platt  half_f1
メンバー数            1          5        300          3 │      —        —
meta_8本         0.0561     0.0383     0.0397     0.0419 │   0.0254   0.0131
meta_6本         0.0750     0.0580     0.0460     0.0656 │   0.0188   0.0100
meta_4本         0.0645     0.0487     0.0433     0.0556 │   0.0150   0.0099
E0_anchor       0.0851     0.0466     0.0624     0.0649 │   0.0317   0.0096
                └──── argmaxを取る系: 0.038〜0.085 ────┘ └ 取らない系: 0.010〜0.035 ┘
```

**効くのはメンバー数ではなく独立性。** ブートストラップのリサンプルは全て同じAから引くので
互いに相関し、増やしても独立な情報が増えない。残る分散は「Aが有限標本であること」に
由来し、Aの内側を何回リサンプルしても消せない。`fold_mean` の5メンバーは互いに素なfoldから
来るので、数は少ないが独立性が高い。

**argmaxを取る限り std 0.04 前後が床**であり、それより下へ行くにはargmaxという操作自体を
やめる（プラグイン系にする）しかない。Lipton+2014のwinner's curseが「argmaxの性質」で
あって「推定の粗さ」ではないことの実測。

## 5. `cbpe_platt` — ホールドアウトでは勝つが、本番切替は保留

CBPE（Average Confidence推定量）は較正済みスコアだけから混同行列を推定する。ラベル不要。

```
TP(t)=Σ_{s>=t} s     FP(t)=Σ_{s>=t}(1-s)     FN(t)=Σ_{s<t} s     TN(t)=Σ_{s<t}(1-s)
```

既存則との違いは2点。(a) train 742行ではなく **test 800行・本番分布の上で**測れる、
(b) **ラベルの実現値に依存しないのでwinner's curseが原理的に起きない**。
前提は較正済みであること — 本モデルは実正例率0.2412 vs 予測平均0.2423 で満たしている。

素の `cbpe` は負けた（-0.0057）。局所較正のズレで低閾値を過小評価するため、
1変数Platt補正が必須だった。`cbpe_platt` は全9モデル中8でΔ>0、閾値分散を46〜77%削減。

### 本番適用の結果 — Publicは落ちた

H58構成の閾値だけ 0.335→0.3973 に変えて提出: **Public 0.8095 → 0.7627（-0.047）**。
混同行列の復元では TP 51→45、消えた8行のうち6行が真陽性だった。

ただし **これは `cbpe_platt` を否定する証拠ではない**。§2の通り8行の変更の1ドローは
SD±0.03〜0.04 で、+0.0122の効果は原理的に検出できない。帯[0.335,0.397)の期待正例率0.44を
当てると期待F1≈0.805 ≒ 現行と同じで、**期待値では中立・引きが悪かった**が正しい読み。

> seed42のOOFではこの帯が予測0.363に対し実測0.909（+0.546）と極端に見えたが、他5シードでは
> +0.08程度で合算p=0.068。**seed42固有の外れ値**であり、局所較正異常という説明は誤り。

**判断**: 本番閾値は `oof_best` のまま維持する。検証するならPublic 1回ではなく、
リピート数を増やしたホールドアウトか、Private確定後の事後検証で行う。

## 結論・今後の対応

- **H58は統合しない。** 実装・スコアは再現するが、正しいベースラインに対してAUC/APは
  5シードで1/5、mean負。docの「相互作用」はベースライン誤りの産物。
- **閾値則は `oof_best` を維持する。** 既存6則は20repでも区別不能。`cbpe_platt` だけが
  CIで0を跨がないが、本番切替は保留。
- **閾値アンサンブルは打ち止め。** argmax系の分散の床0.04に当たっており、メンバーを
  増やしても抜けられない。
- **今後の検証手順**: 着手前に「その効果量はPublicで判定できるか」を計算する。
  この盤面でPublic 1回が判定できるのは0.05以上。それ未満はホールドアウトの
  リピート数で見る。構成比較にF1（OOF最適閾値）を使わない — AUC/APか固定閾値で。
