  ソフト投資比率の高低で購入率が2〜4倍違う**（最小帯で 5.3% vs 31.1%）
- 単変数AUCの上限が 0.66 → **0.72**（`ソフト投資_売上比`）に上がった

#### 10シード判定
```

F1    0.6644           0.6773           +0.0129   7/10
→ ACCEPT（AP基準 0.005 の6倍）
```
- **AUC が 10/10 なのに F1 は 7/10**。F1 は閾値経由で分散が大きいので、判定は AP と AUC を主に見る。

#### 効かなかったもの
- `一人当たり売上`（AUC 0.51）、`流動資産比率`/`固定資産比率`（0.50、恒等式で縛られていて情報なし）

### nb006 — 2問版（アンケート7・10 × 財務）

- **ノートブック**: `アンケート7_10特化_LightGBM.ipynb`
- **提出**: `sub_q710_oofth.csv`（27.25%）/ `sub_q710_ratematch.csv`（24.88%）
- **ユーザー報告で実提出の最高スコア**（Public値は未共有）

#### なぜ2問だけか
11問の単変数AUC（強さ）: Q7 **0.666** / Q10 **0.604** / Q4 0.571 / Q2 0.562 / 残り7問 ≤0.548。
Q7 は**財務列も含めた生の全列の中で1位**。

- Q7 = 既存の業務プロセス改善ツールへの**満足度**（Q6=はいのみ、欠損=未導入）
- Q10 = 外部パートナーとの**DX連携実績**
- どちらも「**小さいほど購入**」= 既存に不満なほど買う / 外部に頼れていないほど買う
- 2問の相関 0.101 でほぼ独立

#### 特徴量6列
```python
fuman = (6 - Q7.fillna(3.5)) + (6 - Q10)      # 3.5 = 未導入は中立
Q7Q10_不満合計 / Q7Q10_両方低 / Q7Q10_積
不満×ソフト投資_売上比 / 不満×営業CFマージン / 不満×自己資本比率
```

#### Q7 の欠損を 3.5 で埋める根拠
水準別購入率 46.4% / 31.9% / 24.7% / 16.9% / 12.7% に対し、
**未導入（Q6=いいえ、356社）は 22.2%** で水準3と4の間。0埋めだと「最も不満」側に置かれる。
※ 0埋め vs NaN vs 3埋めの比較では ΔAP +0.001〜+0.003 で基準未達。
`アンケート７_isna` フラグがあるので木が分離でき、実害は出ていなかった。

#### 判定（10シード）
```

土台のみ                0.8942   0.7433   0.6851   +0.0000  0/10

+財務交互作用まで         0.9083   0.7665   0.7079   +0.0232 10/10   ACCEPT
```

#### 交互作用の中身（4象限、中央値で分割）

営業CFマージンは +13.2pt、自己資本比率は +8.1pt。

### nb018 — LR のカテゴリを one-hot 化（現在の本命）

#### 動機

#### 「線形向きに絞る」は逆効果

標準化＋`C=0.1` の正則化で扱えており、LRにも有用だった。分位変換も逆効果で、
比率の生の目盛りに情報がある。

**多様性が増えても効かない。** lgbm との順位相関は current 0.873 → 絞った版 0.827 と
**絞った版のほうが多様**なのに、アンサンブルは 0/10 で負けた。

> **符号化を直すのは正しいが、列を減らすのは間違い。**
> **多様性はメンバーが有能な範囲でしか効かない。**

## メモ（一般化できた教訓）

- **判定は10シードのペア比較で行う。** 5シードでは判定できない差がある（nb006 の3列版が実例:
  5シードで REJECT → 10シードで ACCEPT）。差が 0.01 以上なら5シードでも全勝するので、
  **Δが0.01未満の候補だけ10シードで確認する**のが効率的。
- **AP の改善は F1 に必ずしも乗らない。** 4問版は AP で 10/10 勝つのに、
  **正例率を揃えると F1 は2問版と互角**（4〜6勝/10）。
  AP は並び順だけ、F1 は閾値の位置に強く依存する。**特徴選択は AP、最終提出は F1 と正例率で見る。**
- **Public に乗るかの目安は「正例率を揃えた F1 が全域で勝っているか」**（2026-08-14 に確認）。
  - nb012 アンサンブル: 24〜28% の**全域**で単体に +0.010〜0.014 → **Public でも最高になった**
  - nb007 4問版: AP は 10/10 だが正例率を揃えると互角（4〜6勝/10）→ **Public では2問版に負けた**
  閾値の当たり外れに依存しない改善かどうかを、この形で先に確認すること。
- **正例率が最大の調整レバー。** OOF F1 の最良は **正例率25%**（学習データの購入率24.12%とほぼ一致）。
  22〜28% は平坦、30%超で落ちる。提出済みの 27.25% は平坦域の右端で 0.003 ほど損。
- **順位平均は使わない。** AP は上がるのに F1 が下がる現象を**5回再現**した。
  順位化で予測が一様分布になり、OOFで決めた閾値が test とズレる。
- **スタッキングより単純平均。** 742行・メタ特徴3〜5列では学習の余地がなく、
  メタにLightGBMを使うと -0.0312 と大崩れ。メタは線形でなければならない。
- **弱い特徴ほど手で交互作用を作る価値がある。** 弱い信号（AUC 0.6前後）は掛け算しないと
  木が使える形にならないが、強い信号（テキスト0.79）は木が自力で相互作用を作れる
  （テキストprob×財務は ΔAP -0.0018 で REJECT）。
- **既にモデルに入っている列を材料に特徴を作っても、木が自力で作れる範囲なら効かない。**
  業界系（nb008）、企業概要TF-IDF（nb005）、手作りキーワード（nb015）はすべてこの形。
- **テキストを1列に圧縮するのが常に最善ではない。** 組織図はTF-IDF列だと -0.0062 なのに、
  `has_DX` フラグにすると +0.0152。圧縮すると業界代理の語彙に支配されて1ビットが埋もれる。
- **多重比較補正を生き延びた発見だけが再現する。** 4本のEDAレポートのキーワードのうち、
  FDR補正後も有意だったのは `has_DX`（q=0.00288）だけで、それだけが実際に効いた。
- **単変数AUCで問（列）を捨ててはいけない。** Q2 は単独で足すと +0.0015 で基準未達なのに、
  Q4 と一緒なら最良になる（相関0.101で独立だから）。
- **多様性はメンバーが有能な範囲でしか効かない。** LRを弱くして相関を下げても
  アンサンブルは 0/10 で負ける（nb018）。
- **チューニングとアンサンブルは代替関係、情報追加とアンサンブルは相補的。**
  Optuna はアンサンブル上で +0.0006、DXフラグは +0.0358。
- **出現率が数%以下のフラグは LightGBM に届かない。** `不満4_全部低`（16社）は
  AP が小数点4桁まで完全一致＝木が一度も分割に使わなかった。
  `組織_has_データ`（18社）も gain 0.0。
- **Public は 240行しかない。** F1 の標準偏差は 0.04 前後。**Public差 0.03未満は判断に使わない。**
- ノートブックは**実行済みの状態で保存**する。マークダウンに書いた数値とセル出力が
  食い違っていないか、設置前に必ず確認する。
- **VSCode でノートを開いたまま編集すると上書きされる。** 一度実測で §7 を失った。
  編集前にタブを閉じてもらう。
