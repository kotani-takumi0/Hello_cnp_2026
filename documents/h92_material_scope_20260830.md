# H92 「何を買うつもりか」＝商材スコープは読めるか — 2026-08-30

商材は**従業員向けDX教育のe-learningプラットフォーム＋スキルアセスメントツール**。
仮説は「モデルが買うと言って外す行（FP）は、**やろうとしている教育がこの商材の
範囲外**（集合研修・OJT・資格支援・社内大学）なのではないか」。

**結論: 支持されない。REJECT。共有する仮定の無い4つの計器が同じ答えを出した。**

| 計器 | 結果 |
|---|---|
| 手書きキーワード辞書（8節までの本文） | FP/TPの向きは10本中5本＝コイン投げ、適合スコアAUC 0.490 |
| 語をデータに選ばせる（char TF-IDF + 入替検定） | FP/TP識別 CV-AUC 0.493、**p=0.250** |
| 教師なし話題（NMF 7話題） | 話題は購入率を 0.078→0.456 に分けるが、それは**熱量軸**。FP/TP は 0.536 |
| 商材説明文との意味的距離（ローカルe5、計器検証済み） | 適合スコア 全体AUC 0.504 / p>0.5内 0.498 / 帯内 0.473 |

裏返しの FN 側では「範囲外モダリティ」の言及が **+0.184** 多い
（CI [+0.024, +0.344]）—— 範囲外の話をしている企業ほど**買っている**。

前提そのものも確かめた。FP を押し上げているのは **E0_anchor（表形式）で +1.68**、
テキストのE3は FP -0.81 / TP -0.65 と**ほぼ同じ**。
つまり FP は「テキストが買いたそうと言っている行」ではなく、
**テキストが FP と TP を区別できていない行**である。

副産物が1つある。**p>0.5 の中で FP と TP を、OpenAI埋め込みのPC1残差だけで
AUC 0.648（入替検定 p=0.050）まで見分けられる**。ただし合成に足すと負け
（ΔAP -0.0026, 3/11）、同じ163行に対して他の3計器（語彙・話題・意味距離）は
いずれも帰無を割らない。**単独の境界値であり、追う価値は低い。**

## 1. なぜ新しい問いなのか

既存のテキスト特徴は**全部「強度」軸**である。

**「何を買うつもりか」＝モダリティと範囲を読む特徴は1本も無い。** ここが空白だった。

## 2. スコープ特徴の作り方

`今後のDX展望` から**教育に触れている文だけ**を抜き（教育文ゼロは742行中3行）、
商材の範囲内/範囲外を語彙で分ける。

- **範囲内**: eラーニング系 / アセスメント系 / 全社リテラシー / 外部調達 / 新規導入
- **範囲外**: 集合・現場型 / 資格支援 / 社外派遣 / 内製化 / 既に保有

`スコープ適合スコア = Σ範囲内 − Σ範囲外`。

## 5. モデルに依存しない上限 — テキストは1次元

`text-embedding-3-large` (3072次元) を、ラベル非依存のPCAでPC1とその残差に分ける。

| | 全体AUC | 帯内 | p>0.5内 |
|---|---:|---:|---:|
| 全3072次元 | 0.749 | 0.541 | 0.566 |
| **PC1だけ** | **0.782** | 0.571 | 0.603 |
| PC1を抜いた残り | 0.540 | 0.522 | 0.569 |

**PC1（DX成熟度）が全部**であり、残りは 0.540 しかない
（[[dx_text_is_one_dimension]] の再確認）。9本目のExpertとして本番の合成に足すと:

```
残差テキスト単体AUC 0.5367
Δ auc -0.00105 (1/11)  ap -0.00260 (3/11)  f1 -0.00169 (2/11)   REJECT
```

スコープ情報がテキストにあって効くなら、この残差の中に無ければならない。無い。

## 6. 唯一の生存線 — FP/TP は残差で 0.648 まで割れる

p>0.5 の163行（TP 140 / FP 23）を、PC1を抜いたテキスト残差だけで分類する:

```

ラベル入替60回の帰無: 平均 0.480  sd 0.083  95%点 0.607
経験的p値 0.050 (3/60)
```

**ちょうど境界。** しかも上位50PCでは 0.521 しか出ず、効いているのは低分散方向である。
FP が23件しかないので、これ単体で何かを主張するには弱い。そして5節の通り、
同じ残差を合成に足すと負ける。

つまり「テキストに何か残っている」可能性は完全には消えていないが、
**今の埋め込みの取り方では取り出せない**。

## 7. 別角度からの再検証 — 辞書に依存しない3計器＋前提の検査

3〜6節の計器（手書きキーワード）は私が数十件読んで作ったものなので、
**帰無が語彙の下手さのせいである可能性**が残る。共有する仮定の無い計器で潰す。

### 7.1 角度A: 前提の検査 — FPは本当に「テキストが買いたそう」な行か

Expertごとのlogit平均（高い＝買うと言っている）:

| Expert | FP(23) | TP(140) | FN(39) | TN(540) | FP-TP |
|---|---:|---:|---:|---:|---:|
| **E0_anchor** | -0.00 | 1.67 | -1.81 | -4.35 | **-1.68** |
| E0b_linear | 0.24 | 1.33 | -1.10 | -3.07 | -1.09 |
| E7_cross | -0.04 | 0.55 | -0.96 | -2.58 | -0.59 |
| E6_manual | -0.63 | -0.12 | -1.16 | -2.11 | -0.51 |
| E1_finance | -0.48 | -0.23 | -1.16 | -2.43 | -0.26 |
| E2_survey | -1.12 | -0.90 | -0.99 | -1.42 | -0.22 |
| **E3_dx_text** | **-0.81** | **-0.65** | -1.09 | -1.46 | **-0.16** |
| E4_org_text | -0.95 | -0.93 | -1.03 | -1.30 | -0.02 |

FPをTNから引き離しているのは **E0_anchor（表形式）で +4.35**。
そしてテキストのE3は **FPとTPでほぼ同値**（-0.81 / -0.65、上位半分に入る割合は
FP 87% / TP 90%）。

**つまりFPは「テキストが買いたいと言っているのに買わない行」ではなく、
「テキストがFPとTPを区別できていない行」である。** 仮説の前提が半分崩れている。

### 7.2 角度B: 語をデータに選ばせる

教育文の char_wb 2-4gram TF-IDF で FP vs TP を教師あり分類（`p>0.5` の163行）。

```
FP/TP識別 CV-AUC 0.493   帰無(入替40回) 平均 0.460 sd 0.078 95%点 0.593   p=0.250
```

**帰無を割らない。** 係数を読むと、FP側に効くのは
「絞っ」「負荷や」「既存の」「短期」——**モダリティ語ではなく抑制語**。
TP側は「全社員」「基礎」「制度」「に加え」。範囲の話は出てこない。

ローカルの `intfloat/multilingual-e5-base` で、各社の教育文と
**商材の説明文**（「従業員向けのDX教育のeラーニングプラットフォームを導入し、
デジタルスキルを測定・可視化するアセスメントツールを全社に展開する」）および

### 7.5 4計器が一致した意味

手書き辞書・自動語彙・教師なし話題・意味的距離——**仮定を共有しない4つが全部同じ答え**。
テキストから読み取れるのは一貫して「熱量（DX成熟度）」であって、「範囲」ではない。

そして角度Aの通り、そもそもFPを押し上げているのは表形式のE0であって、
テキストではない。**「テキスト上は買いたそうなのに外す」という現象自体が、
測ってみると存在しない。**

## 8. もしAPIを自分で回すなら

埋め込みの再取得は勧めない。`text-embedding-3-large` を別モデルに替えても、
出てくるのは同じ成熟度軸（5節）である。

**測るべきは、埋め込みが平均で潰す「1社について1つの明示的な判断」**。今日の測定から
候補は2つ:

1. **既に教育商材を保有しているか**（`既に保有` は FP 0.304 / TP 0.207、
   p>0.5内AUC 0.451）。アンケート６が聞いているのは**業務プロセス改善ツール**であり、
   教育商材ではない（テキスト印との相関 -0.141 ＝ 別物）。**42列に無い唯一の商材固有情報**。
2. **6節の低分散方向が何なのか**を人が読める形にする（FPとTPを各20件ずつ読ませ、
   差を言語化させる）。

設計上の必須条件（過去の失敗から）:

- **ラベルを見せない**。抽出は行単位の決定的変換に留め、CVはローカルで回す
  （`colab_openai_embed.py` の docstring と同じ運用）。
- 出力は**JSONの固定スキーマ**（score / status / confidence / evidence / reason）。
  `data/llm_make_or_buy/*_raw.jsonl` が実績のある形。
- **一度取ったら再取得しない**。npz/csv を唯一の真実にする。
- 評価は `exp/compare_material_scope.py --mode ceiling` の3節と同じく
  **9本目のExpertとして11seedのscreen** → 通ったら strict。
  単体AUCが高くても合成で負ける実例が本プロジェクトに多数ある
  （[[evaluate_by_meta_contribution]]）。

期待値は正直に言って高くない。LLM3軸は AUC 0.780 ＝ PC1 とほぼ同じ値を再発見しただけ
だった。**同じことを繰り返さないために、聞くのは「熱意」ではなく「事実」**
（既に持っているか / 何を買うか）に限ること。

## 9. その事実が取れたとして、F1に効くのか（VOI）

抽出できることと役に立つことは別なので、**APIを叩く前に必要な性能を計算する**。

### 9.1 前向きシミュレーション — どれだけ強ければ効くか

出現率20%の二値の事実を作り、単体AUCを変えながら9本目の入力として本番foldに足す
（11seed × 3draw、メタは非負重みなので `B` と `1-B` の両方を渡して符号を自由にする）。

| その事実の単体AUC | ΔAUC | ΔAP | ΔF1 | ΔAP>0 | 判定 |
|---:|---:|---:|---:|---:|---|
| 0.500 | -0.0005 | -0.0005 | -0.0016 | 5/11 | REJECT |
| 0.525 | -0.0001 | +0.0003 | -0.0005 | 7/11 | REJECT |
| **0.550** | +0.0008 | **+0.0026** | +0.0018 | 9/11 | **ACCEPT (弱い)** |
| **0.600** | +0.0035 | **+0.0096** | +0.0082 | 11/11 | **ACCEPT (明確)** |
| 0.650 | +0.0070 | +0.0195 | +0.0192 | 11/11 | ACCEPT (明確) |
| 0.750 | +0.0143 | +0.0412 | +0.0443 | 11/11 | ACCEPT (明確) |

**損益分岐は単体AUC 0.55、明確に効かせるには 0.60。**

重要な但し書き: このシミュレーションの `B` は **y を条件に既存Expertと独立**、つまり
**完全に直交する理想の事実**である。実際の抽出は既存列と相関するので、
この曲線は**上界**。現実の必要水準はこれより高い。

参照点として、キーワード版の『既に保有』は単体AUC **0.530** で分岐点に届かない。
LLM抽出はこれを明確に超える必要がある。

### 9.2 拒否ルールとして使う場合 — 必要な精度は 1 − F1/2

『既に保有』の印が付く高p行は36件。内訳は **非購入7件（直る）+ 購入29件（壊れる）**。

```
現状(閾値0.5): TP 140 / FP 23 / FN 39   F1 0.8187
全部0に倒すと: TP 111 / FP 16 / FN 68   F1 0.7255  (-0.0932)
```

損益分岐を解くと、**落とす行数によらず「落とした行の59.1%が非購入」が必要**になる。
これは一般則で、`F1 = 2TP/(2TP+FP+FN)` の下では

```
拒否の精度 > 1 − F1/2        （F1=0.8187 なら 0.5906）
```

現在の基準（高p行の非購入率）は **0.141**、印が付く行でも **0.194**。
**4.2倍のリフトが要る。** そしてF1が高いほど拒否の条件は厳しくなる。

### 9.3 パイロットで止められるか — 必要な行数

抽出を全1542行に走らせる前に、trainの一部で単体AUCを測って判断したい。

| パイロット行数 | AUC=0.60のSE | 0.5と区別するz | 80%検出力 |
|---:|---:|---:|---|
| 200 | 0.048 | 2.07 | × |
| 300 | 0.039 | 2.54 | × |
| **500** | 0.031 | **3.28** | **○** |
| 742(train全部) | 0.025 | 3.99 | ○ |

AUC 0.55 を 0.5 と区別するには **1500行必要**（train全部でも足りない）。

**したがって: 狙うのは 0.60 以上が見込める事実だけ。パイロットは500行。
そこで 0.60 を超えなければ本抽出に進まない。** 0.55前後の微妙な事実は、
仮に本当に効いていても 742行では判定できないので、追ってはいけない。

### 9.4 実物を判定装置にかける — 単体AUCは基準にならない（9.1の訂正）

9.1はシミュレーションなので、**実物を本番foldの判定装置にかけた**（11seed）。
語彙由来の3つは `--mode candidates` で再現できる。`nmf_7topics` と `e5_6anchors` は
`--mode angles` が作る特徴に同じ手続きを当てたもの。

| 候補 | 単体AUC | ΔAUC | ΔAP | ΔF1 | ΔAP>0 | 判定 |
|---|---:|---:|---:|---:|---:|---|
| scope_10flags | 0.586 | +0.0001 | +0.0001 | +0.0007 | 2/11 | REJECT |
| **nmf_7topics** | **0.740** | -0.0002 | **-0.0002** | -0.0003 | 4/11 | **REJECT** |
| e5_6anchors | 0.561 | -0.0001 | -0.0001 | -0.0012 | 5/11 | REJECT |
| 既に保有のみ | 0.508 | -0.0000 | +0.0005 | -0.0004 | 6/11 | REJECT |
| スコープ適合スコアのみ | 0.477 | -0.0000 | -0.0000 | +0.0000 | 2/11 | REJECT |

**NMF話題は単体AUC 0.740。** 9.1の表なら ΔAP +0.04 の「ACCEPT(明確)」の水準である。
それが REJECT になる。理由は重なりで、既存モデルとの関係を測ると:

| 候補 | 単体AUC | E3との相関 | 合成pとの相関 | **合成pを除いた残差AUC** |
|---|---:|---:|---:|---:|
| scope_10flags | 0.571 | 0.322 | 0.192 | **0.481** |
| nmf_7topics | 0.744 | **0.805** | 0.488 | **0.528** |
| e5_6anchors | 0.560 | 0.248 | 0.102 | **0.511** |
| 既に保有のみ | 0.511 | 0.053 | 0.054 | **0.354** |
| （参考）E3_dx_text 自身 | 0.789 | — | 0.614 | 0.536 |

- **nmf_7topics は E3 と相関 0.805 ＝ 実質E3である。** 単体0.744はE3の作り直し。
- scope_10flags は合成pとの相関が 0.192 と低い＝直交してはいるが、
  **残差AUC 0.481＝直交しているのは情報ではなくノイズ**。
- 既に保有は残差AUC 0.354で、合成pを除くと**符号が反転する**
  （＝スコアを所与にすると「持っている企業ほど買う」側に寄る）。

**したがって 9.1 の「単体AUC 0.55が損益分岐」は基準として使ってはいけない。**
9.1のシミュレーションの `B` は y を条件に独立＝**全部が残差**だったので、
あの表が本当に言っているのは:

```
残差AUC（合成pを除いた後）0.55 が損益分岐、0.60 で明確
```

**パイロットの判定条件もこれに差し替える。** 抽出した事実の単体AUCではなく、
**そのOOF確率から合成pの寄与を除いた残差のAUC**を見る。
E3自身の残差AUCが 0.536 であることを踏まえると、これは相当に高いハードルである。
