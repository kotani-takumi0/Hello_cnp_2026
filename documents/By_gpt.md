# By GPT — 次の実験方針

## 1. 現在地

評価指標は **F1Score（binary）**。  
教師データは `購入フラグ`、モデル内部では購入スコア・購入確率を出し、最後に閾値で `0 / 1` に変換する。

現時点の主な結果は次の通り。

| 実験 | Public F1 | OOF F1 | OOF AUC | 閾値 | 概要 |
|---|---:|---:|---:|---:|---|
| baseline | 0.6029 | 0.6667 | 0.8621 | 0.220 | 表形式LightGBM |
| baseline + H1 | 0.6111 | 0.6569 | 0.8648 | 0.205 | 利益率特徴 |
| baseline + H1 + H8 | 0.6838 | 0.7500 | 0.9324 | 0.295 | `今後のDX展望` TF-IDFスタッキング |
| baseline + H1 + H8b | **0.7040** | 0.7236 | 0.9251 | 0.220 | `企業概要`も追加した現ベスト |

重要な発見は、`今後のDX展望`が既存アンケートとほぼ無相関であり、独立した強い信号源だったこと。  
一方、単一seedのOOF F1ではH8がH8bを上回ったが、PublicではH8bが勝った。したがって、単一seedのF1だけでモデル選択してはいけない。

## 2. 提案されたLLM購入スコア列について

### 結論

**実験する価値はある。ただし、LLMの出力を最終予測にせず、補助特徴量として使う。**

作る列の名前も `LLM購入確率` より、次のようにした方が正確。

```text
llm_purchase_score
```

LLMが返す0〜1の値は、統計的に校正された購入確率ではない。  
そのため、「確率」として直接提出するのではなく、LightGBMなどへ追加する1特徴量として扱う。

```text
TF-IDFモデル
企業概要
組織図
今後のDX展望
        ↓
LLM
        ↓
llm_purchase_score
LLM構造化特徴
        ↓
既存のLightGBMへ追加
        ↓
最終購入スコア
        ↓
閾値
        ↓
0 / 1
```

## 3. LLMへTF-IDFの何を見せるか

### やってはいけない入力

TF-IDFの数万次元の疎ベクトルを、そのままLLMへ渡しても意味はない。

```text
[0.000, 0.014, 0.000, 0.052, ...]
```

LLMはこのベクトルの各次元がどの語句に対応しているか理解できない。

### 見せるべき情報

各企業について、TF-IDFモデルが判断に使った情報を、人間が読める形へ変換する。

1. TF-IDFモデルのOOF購入スコア
2. 購入方向に寄与した上位語句
3. 未購入方向に寄与した上位語句
4. `今後のDX展望`
5. `企業概要`
6. `組織図`

入力例：

```text
【TF-IDFモデル情報】
OOFスコア: 0.67

購入方向への寄与語句:
- 全社展開
- 投資を拡大
- 来年度から導入
- 基幹システム刷新

未購入方向への寄与語句:
- 慎重に検討
- 当面は
- 最小限

【今後のDX展望】
...

【企業概要】
...

【組織図】
...
```

### なぜTF-IDFスコアだけでは足りないか

TF-IDFスコアだけを見せると、LLMはその値を言い換えるだけになりやすい。

```text
TF-IDFスコア 0.67
→ LLMスコア 0.70
```

これでは新しい情報がほとんど増えない。

上位寄与語句と企業概要・組織図を一緒に見せることで、

- DX投資意欲は高いが、意思決定部署が弱い
- 企業規模は大きいが、計画が具体化していない
- DX推進部署が経営層に近く、実行可能性が高い
- 前向きな単語はあるが、過去の取り組みを説明しているだけ

といった、TF-IDF単体では捉えにくい関係をLLMに評価させる。

## 4. LLMへ出させる値

購入スコア1列だけでは、なぜその値になったか分からず、再利用もしにくい。  
次の構造化特徴も同時に出させる。

```json
{
  "llm_purchase_score": 0.68,
  "dx_investment_strength": 4,
  "plan_specificity": 3,
  "implementation_urgency": 3,
  "companywide_scope": 4,
  "external_vendor_need": 2,
  "decision_making_readiness": 3,
  "organization_dx_readiness": 2,
  "cautiousness": 1,
  "evidence_consistency": 3,
  "confidence": 3
}
```

推奨スケール：

```text
0 = 根拠なし、または非常に弱い
1 = 弱い
2 = 中程度
3 = 強い
4 = 非常に強い
```

`llm_purchase_score`のみ0〜1、それ以外は0〜4に固定する。

### 重要

LLMへ実際の `購入フラグ` は渡さない。  
「購入企業の例」を全データから選んでfew-shotとして渡すこともしない。

購入ラベルを使った例示を行う場合は、外側foldの学習部分だけから例を選び、検証foldの情報を絶対に含めない必要がある。最初の実験では、固定ルールによるzero-shot抽出の方が安全。

```text
文章に書かれていない情報を推測してはいけません。

企業概要、組織構造、今後のDX計画との整合性を確認してください。

特に次を区別してください。

- 今後積極的に投資するという記述
- 単なる検討

{dx_text}

```

## 6. 学習データでのリーク防止

ここが最重要。

### TF-IDFスコア

学習行に渡すTF-IDFスコアは、必ずその行を学習に使っていないモデルのOOFスコアにする。

```text
自分自身を学習したTF-IDFモデルのスコア
→ 使用禁止

自分自身を除外したfoldモデルのスコア
→ 使用可能
```

### TF-IDF寄与語句

上位寄与語句も、その行を学習に使っていないfoldモデルから算出する。

ロジスティック回帰なら、各n-gramの行別寄与は概ね次で計算できる。

```python
row_contribution = tfidf_value * logistic_regression_coefficient
```

正の値が大きい語句を購入方向、負の値が小さい語句を未購入方向として抽出する。

### LLM特徴

LLM自体は購入ラベルを見ないため、固定プロンプトによる特徴抽出だけなら、全行を同じ処理で変換できる。

ただし、入力に含めるTF-IDFスコアと寄与語句は、必ずcross-fitされたものを使う。

## 7. testデータの処理

testについては、5foldモデルの予測を平均したTF-IDFスコアを使う。

```python
test_tfidf_score = np.mean(
    test_scores_from_each_fold,
    axis=0
)
```

寄与語句も、各foldモデルで得た寄与を平均または多数決して、安定して上位に出た語句を使う。

LLM APIは、trainとtestを合わせて1企業につき1回に抑える。

同じ企業へfoldごとに5回LLMを呼ぶ必要はない。

## 8. LLM特徴の評価方法

### 基準モデル

```text
H8b
= 表形式 + H1 + TF-IDF（DX展望＋企業概要）
```

### 比較する実験

| ID | 内容 |
|---|---|
| L0 | H8b |
| L1 | H8b + `llm_purchase_score` |
| L2 | H8b + LLM構造化特徴 |
| L3 | H8b + `llm_purchase_score` + LLM構造化特徴 |
| L4 | H8b + TF-IDF寄与語句を見せないLLM特徴 |
| L5 | H8b + TF-IDF寄与語句を見せたLLM特徴 |

L4とL5を比較することで、TF-IDF情報をLLMへ渡す意味があったか確認できる。

### 採用基準

単一seedのF1だけで判断しない。

最低限、10seedのペア比較を行う。

確認する値：

```text
F1平均
F1標準偏差
AP平均
AUC平均
候補が基準を上回ったseed数
最適閾値の分散
TF-IDFスコアとLLMスコアの相関
```

目安：

```text
平均F1が +0.005以上
10seed中7seed以上で改善
APが大きく悪化しない
閾値の分散が極端に増えない
```

### 相関の見方

```python
np.corrcoef(
    tfidf_oof_score,
    llm_purchase_score
)[0, 1]
```

- 相関0.95以上：TF-IDFの言い換えになっている可能性が高い
- 相関0.70〜0.90：一部補完している可能性
- 相関0.70未満：独立性は高いが、LLMが不安定なだけの可能性もある

相関が低ければ良いという話ではない。F1/APの改善とセットで判断する。

## 9. Embeddingとの比較

LLM直接スコアとEmbeddingは別実験として比較する。

### Embedding案

```text
今後のDX展望
→ Embedding
→ LogisticRegression
→ embedding_oof_score
```

または、

```text
今後のDX展望
企業概要
→ 別々にEmbedding
→ 別々のLogisticRegression
→ dx_embedding_score
→ overview_embedding_score
```

### 優先順位

1. 閾値評価の厳密化
2. H8とH8bの複数seed比較
3. Embeddingスコア追加
4. LLM構造化特徴追加
5. LLM直接購入スコア追加
6. EmbeddingとLLMの併用

理由：

- Embeddingは再現性が高い
- 一度ベクトル化すれば繰り返し実験できる
- LLM直接スコアはプロンプト依存が大きい
- LLMが返す値は校正された確率ではない
- LLMの強みは購入確率そのものより、構造化特徴抽出にある

したがって、LLM購入スコア案は却下ではないが、本命ではなく比較対象として扱う。

## 10. 閾値戦略

現在のOOF確率全体に対して、同じOOFラベルを使って最適閾値を選ぶと、閾値へ多少過学習する。

より厳密には、外側foldごとに次を行う。

```text
外側train
    ↓
内側OOF予測
    ↓
内側OOFだけで閾値決定
    ↓
外側valid予測
    ↓
内側で決めた閾値を外側validへ適用
```

外側validの正解ラベルで閾値を決めてはいけない。

### 頑健な閾値

最大F1を取る一点ではなく、最大F1から0.002以内の閾値範囲の中央値を使う。

```python
best_f1 = f1_scores.max()

stable_thresholds = thresholds[
    f1_scores >= best_f1 - 0.002
]

robust_threshold = np.median(stable_thresholds)
```

### 正例率カットも比較

確率閾値だけでなく、購入スコア上位何%を1にするかも比較する。

```text
上位22%
上位24%
上位26%
上位28%
上位30%
```

ただし、学習データの正例率24.1%へ機械的に合わせてはいけない。H8とH8bの結果から、test正例率がtrain正例率に近いことは優位性の根拠にならないと分かっている。

## 11. 推奨する次の実行順序

### Step 1

H8とH8bの10seedペア比較を完了する。

```bash
python exp/compare_h8_h8b.py
```

以降の基準モデルを決める。

### Step 2

H8bへネスト型閾値評価を実装する。

比較：

```text
全OOFで一点最適化
ネスト閾値
複数seed閾値の中央値
上位率カット
```

### Step 3

Embeddingスコアを1列追加する。

```text
H8b + dx_embedding_score
```

10seedで評価する。

### Step 4

LLMの構造化特徴だけを作る。

```text
H8b + LLM構造化特徴
```

購入スコアをまだ入れず、構造化特徴の追加価値を確認する。

### Step 5

TF-IDF情報を見せたLLM購入スコアを追加する。

```text
H8b
+ llm_purchase_score
+ LLM構造化特徴
```

### Step 6

最終候補を2系統に分ける。

候補A：

```text
H8b
+ 複数seedアンサンブル
+ 頑健な閾値
```

候補B：

```text
H8b
+ Embedding
+ LLM構造化特徴
+ 複数seedアンサンブル
+ 頑健な閾値
```

提出可能ファイルが2つなので、同じモデルの僅かな閾値違いより、異なる特徴構成の2本を残す。

## 12. 最終判断

TF-IDFの情報、企業概要、組織図をLLMへ見せ、購入スコア列を作る案は、**補助特徴量としてなら妥当**。

ただし、次の条件を守る。

1. TF-IDFの疎ベクトルではなく、OOFスコアと上位寄与語句を渡す
2. 学習行のTF-IDF情報は必ずcross-fitする
3. LLMへ購入フラグを渡さない
4. LLMスコアを確率として信用しない
5. 最終予測ではなくLightGBMへの追加特徴にする
6. 構造化特徴も同時に出力する
7. 10seedペア比較で追加価値を確認する
8. Embeddingとの公平な比較を行う

現状の最重要課題は、新しい特徴を増やすことだけではない。  
**モデル比較と閾値選択の分散を下げ、再現可能な評価基盤を作ること**が先にある。

TF-IDFによる大幅改善はすでに成功している。次は、その信号を壊さず、EmbeddingとLLMが本当に独立した情報を追加しているかを検証する段階。
