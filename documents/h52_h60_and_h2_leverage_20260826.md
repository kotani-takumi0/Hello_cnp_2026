## 2. H54 — E1 target-freeな会計恒等式重複削除 → 監査込みでREJECT(中立)

FINANCE_COLS(19列の生金額)をsigned-log変換後Spearman相関で検査。

**しきい値0.85〜0.90は危険**: 「企業規模」という単一潜在因子で総資産・流動資産・固定資産・
負債・純資産・自己資本の6列が連鎖的に1塊へ併合され、レバレッジ情報(負債/自己資本の対比)を
壊す。しきい値0.97まで上げて連鎖を解くと、会計上ほぼ同一の4組だけが残った:

```
総資産≒流動資産≒固定資産 (rho>=0.991)   純資産≒自己資本 (rho=0.999)
営業利益≒経常利益 (rho=0.993)           当期純利益≒営業CF (rho=0.997)
```

代表列は「欠損率最小→数値安定性→解釈可能性」の順(target APでは選ばない)。
`H54_FINANCE_DROP_COLS = ("流動資産","固定資産","純資産","経常利益","営業CF")` で19→14列。

```
Development  meta_8本 ΔF1 +0.0012 (8/15)   REJECT(ノイズと区別できず)
Audit        meta_8本 ΔAP -0.0014 (5/10) ΔF1 -0.0010 (4/10)  REJECT(ノイズ)
E1単体: AUC/APともほぼフラット
```

**H52+H54を合成しても同じ結論**（Development ΔF1+0.0016 8/15、Audit ΔAP-0.0014 ΔF1-0.0010、
両方REJECT ノイズと区別できず）。単体で中立な変更を2つ重ねても中立のまま。

各項目を既知スケールで0-1へ線形写像し群内平均(`add_h57_subscales`, `survey_features.py`)。

## 7. H2+H7-both4の実装、バグ、Public急落、原因究明、修正、再確定

### 7.1 初回実装とPublic急落

`h2_financial_health`の4列(自己資本比率・負債比率・ROA・ROE)のうち負債比率・ROEを、
`h7_cash_slack`のFCF比率・現金ROAへ差し替え(`--h2h7-both4`)。

初回ホールドアウトは境界線(meta_8本 ΔAUC+0.0010 10/15=検出基準にわずかに届かず、
ΔAP+0.0056 12/15、ΔF1+0.0079 9/15 → REJECT ノイズと区別できず)。それでも試しにPublic提出。

**Public 0.7438**(exp032の0.8000、H2-both4の0.7797より大幅に低い)。

### 7.2 原因究明: 混同行列の復元

既知のPublic正例59件から逆算(F1=90/121で一致):

```
                 TP  FP  FN   Recall
exp032           52  19   7    0.881
H2+H7-both4(初回) 45  17  14    0.763   ← FNが7→14で倍増
```

exp032→H2+H7-both4で1→0に転じた21社を財務データで調査すると、うち4社が
負債比率17〜26倍という極端な高レバレッジ企業(自己資本比率3.6〜5.3%)。

`負債比率`(=負債/自己資本)はtrain実測で **std=588、min=-16013** という病的に不安定な比率
(分母の自己資本が薄い企業で爆発する)。しかも train で確認すると、この層の関係は弱い:

```
負債比率>=10の45社: 購入率33.3%(全体24.1%よりやや高い程度)
負債比率>=3 かつ ROE>=0.05 の43社(=転落した21社の特徴と一致): 購入率20.9%(全体より低い)
```

→ 「高レバレッジ×高ROEほど買う」という関係は薄いノイズに近く、負債比率という不安定な比率が
少数の企業の予測を大きく揺らしていた、という仮説を立てた。

### 7.3 まさかのバグ発覚

この根本原因調査の**最中に実装バグが発覚**。`--h2h7-both4`や`--h2-stable-leverage`のような
新フラグを単体指定すると、E0からDX展望_の手動辞書を削除する条件には新フラグが
入っていたのに、**その代替であるLLM4軸スコアを追加する`llm_makebuy`条件には入れ忘れていた**。

結果、これらのフラグを使った全ての実験で、E0が「DX展望_を削っただけで代替なし」という
二重に劣化した状態になっていた。`holdout_check.py`と、実際に提出物を作る
`ensemble_experts.py`の両方に同じ抜け漏れがあり、両方修正した。

**影響**: 7.1〜7.2で見たPublic 0.7438の提出物と、そこから逆算した根本原因分析(負債比率の
不安定性)は、この壊れたE0の上で行われていた。負債比率の数値的不安定性(std=588)自体は
事実として残るが、「これが今回のPublic急落の主因」と結論づけるにはこの交絡を除いた
再検証が必要だった。

### 7.4 バグ修正後の再検証

**H2+H7-both4(修正後)**:

```
5rep   meta_8本 ΔAUC+0.0020(5/5) ΔAP+0.0061(5/5)  ACCEPT(明確)
15rep  meta_8本 ΔAUC+0.0013(12/15) ΔAP+0.0065(14/15) ΔF1+0.0084(10/15)
       baseline AUC0.9620/AP0.8970/F10.8068 → 候補 AUC0.9633/AP0.9035/F1 0.8152
       判定 => ACCEPT(明確)
```

バグ修正前(10/15, 12/15)より勝率が上がり、AP勝率14/15(93%)は本セッション最高水準。
「バグによる劣化が本物の改善を覆い隠していた」という仮説が実測で裏付けられた形。

提出物再生成(キャッシュ破棄): `submission_ensemble_experts_seed42_aauto_concatemb_crosslr_lin0.03_h2h7both4.csv`
OOF AUC0.9627/AP0.8950/F1 0.8235、正例225件。**Public 0.784**。

### 7.5 レバレッジ比率の非対称ルーティング(H2-stable-leverage)

負債比率を安定版`負債資産比率`(=負債/総資産、std=0.22)へ置換する実験は、
**木(E0)と線形(E0b)で正反対の反応**という興味深い結果になった:

```
E0b_linear(線形) ΔAUC+0.0065(5/5) ΔAP+0.0080(4/5) ΔF1+0.0214(5/5)  ACCEPT(明確)
E0_anchor(木)    ΔAUC-0.0032(2/5) ΔAP-0.0115(1/5) ΔF1-0.0284(0/5)  REJECT(明確な悪化)
```

解釈: 木は極端な外れ値(17〜26倍)をそのまま綺麗な分割点として使えるが、線形モデルは
同じ外れ値のせいで正常な企業側の情報(94%の非極端レバレッジ企業)がほぼ潰れていた。
→ **E0はそのまま、E0bだけ負債資産比率に差し替える非対称ルーティング**を採用。

```
15rep  meta_8本 ΔAUC+0.0005(9/15) ΔAP+0.0008(7/15) ΔF1+0.0094(11/15)
       判定 => REJECT(ノイズと区別できず、方向はプラス)
```

E0b単体の改善は本物(バグ修正後も完全に同じ数字で再現、かつE0_anchor/meta_7本は
バグ修正の健全性チェックとして寸分違わずゼロ差)だが、8本中の1本の改善では合成全体を
明確に押し上げるには至らなかった。Public 0.7863(直近では2番目に良い数字)。
