### exp002 — baseline + H1（利益率3本）
- **スクリプト**: `exp/make_submission_h1.py`
- **提出ファイル**: `submission/submission_h1.csv`（800行 / 予測正例273）
- **OOF AUC**: 0.8648 / **OOF AP**: 0.6948 / **OOF F1**: 0.6569 @ th=0.205（SEED=42）
- **日付**: 2026-08-03

#### 追加特徴（H1: 収益性の正規化）
- `営業利益率`=営業利益/売上, `経常利益率`=経常利益/売上, `純利益率`=当期純利益/売上
- baseline(exp001)と同一手順（SEED=42, 5fold平均, OOF閾値, カテゴリ定義をtrainで固定）

#### 判定と結果（重要）
- **仮説検証(H1)の結論は PARK**：ペア比較(N=3スモーク & N=15)で ΔAUC は一貫して正（15seedで14/15）だが、
  F1に直結する ΔAP は基準未達 → 「順位付けは改善するがF1関連の正例側は改善弱い」。
- SEED=42単一の **OOF F1 は 0.6569 < baseline 0.6667**（差はノイズ範囲、F1のseed間std≈0.013）。
- **しかし Public F1 は 0.6111 > baseline 0.6029（+0.0082）**。
  → OOF-F1の劣位はノイズで、H1の実体（AUC改善＝順位付けの改善）がPublicに汎化したと解釈できる。
  検証で ΔAUC が一貫して正だった事実と整合。
- 注意: Publicは30%(≈240行)でPublic F1もノイズを含む。+0.0082が確実な優位とは断定不可だが方向性はH1支持。
- 実測ノイズ: 乱数特徴でも単seed F1は+0.013出る → 単seed F1で優劣を判断してはいけない。
- 検証基盤: `exp/harness.py`（複数seedペア比較）, `exp/decision.py`（判定ルール）, `exp/hypothesis_log.md`。

### exp004 / exp005 — baseline + H1 + H8（テキストスタッキング）
- **スクリプト**: `exp/make_submission_h1_h8.py`（`--overview` で H8b）
- **特徴生成**: `exp/text_features.py`
- **日付**: 2026-08-04

#### 発見（なぜテキストが効くのか）
- `今後のDX展望` は平均852文字の自由記述。**単体**の char_wb(1-3) TF-IDF + LR で
  OOF AUC=0.786 / AP=0.509（ベースAP=0.241）。
- 決定的なのは**アンケート1〜11との相関が全て |r|<0.08**（ほぼ無相関）で、
  かつアンケート単独AUCは0.39〜0.55と無力 → テキストは**完全に独立した信号源**。
- 極性語が強い: 「慎重」を含むと購入率 **44%→12.6%**。「最小限」「当面」「見送」も強い負。
  一方「積極」は差+0.015でほぼ無力 → **過去の姿勢**の記述に使われるため。
  テキストは「これまで」と「今後」を書き分ける構成で、単語有無フラグでは方向を取り違える。
  → 文脈を教師ありモデルに任せて1次元に圧縮するのが正解だった。
- TF-IDFのC(0.3〜30)・min_df(2〜10)はほぼ無感応 → チューニング依存ではなく語彙自体に信号がある。

#### 手法（リーク防止が肝）
fold_transform / fold内で完結させるネストCV:
- fold train部分 → **内側5foldのOOF予測**（自分の正解を見ない）
- fold valid部分 → fold train全体で学習したテキストモデルの予測
- test → 同じくfold train全体で学習したモデル（**foldごとに作り直す**）
  ※全trainで1回だけ学習してtest特徴を作ると、train側(内側OOF)とtest側(full-fit)で
    特徴の分布がズレるため避けた。

#### スモーク検証（N=3, baseline=H1とのペア比較）
```
指標    baseline        候補            Δmean    正/n
AP    0.7016±0.0056  0.8317±0.0073  +0.1301   3/3
AUC   0.8706±0.0053  0.9319±0.0019  +0.0613   3/3
F1    0.6692±0.0132  0.7375±0.0054  +0.0683   3/3
判定 => ACCEPT (明確)   ※基準 MIN_MEAN_AP_CLEAR=0.005 の26倍
```
- **15seedの本判定は未実施**（`python exp/run_hypothesis.py H8`）。

#### H8 vs H8b（企業概要の結合）— Publicで決着: **H8bの勝ち**

| | テキスト単体AP | 単seed OOF F1 | **Public F1** | test正例率 |
|---|---|---|---|---|
| H8 (DX展望のみ) | .509 | 0.7500 | 0.6838 | 25.3% |
| H8b (+企業概要) | **.560** | 0.7236 | **0.7040** | 28.6% |

#### 決着: 10seedペア比較（`exp/compare_h8_h8b.py`）→ **H8 の勝ち。Publicはノイズだった**

```
H8  vs baseline(H1): ΔAP +0.1207 (10/10), ΔAUC +0.0587 (10/10), ΔF1 +0.0604 (10/10)  ACCEPT(明確)
H8b vs baseline(H1): ΔAP +0.1092 (10/10), ΔAUC +0.0535 (10/10), ΔF1 +0.0501 (10/10)  ACCEPT(明確)
H8b vs H8         : ΔAP -0.0115 ( 1/10), ΔAUC -0.0051 ( 0/10), ΔF1 -0.0103 ( 0/10)  REJECT
```
- AUC/F1 は **10seed中0seed** しか H8b が勝たない。742行×10seedでこの一貫性。
- 対して Public差 +0.0202 は、ペア・ブートストラップ（800行中139行だけ予測が違う条件で
  240行を抽出）で **0.57σ、同等以上の差が出る確率 0.56** → 完全にノイズ。
- → **今後の基準モデルは H8（今後のDX展望のみ）**。企業概要は入れない。

#### 判断プロセスの反省（重要）
1. 提出前: 単seed OOF F1 (0.7500 vs 0.7236) で H8 を本命と判断 → **1点推定による判断**
2. Public後: Public F1 (0.6838 vs 0.7040) で H8b に乗り換え → **これも1点推定による判断**
3. 10seed後: H8 が正しかった

結論の当否ではなく **手続きが2回とも同じ誤り**だった。Public は30%（240行）しかなく、
F1の標準偏差は単体で約0.05、モデル間差でも約0.035。**Public差 0.03未満は判断に使えない。**
`test正例率がtrain正例率に近い` も根拠にならない（H8=25.3%, H8b=28.6%, 学習=24.1%）。

#### CVとPublicが食い違った真因: 閾値の過学習
| | seed42 OOF F1 | 10seed平均 | seed42 閾値 | 10seed平均閾値 |
|---|---|---|---|---|
| H8 | 0.7500 | 0.7313 | **0.295** | 0.260 |
| H8b | 0.7236 | 0.7210 | 0.220 | 0.280 |

提出に使った seed42 で H8 は OOF F1 が平均より +0.019 高く、閾値も平均から大きく外れた
= **たまたま良く出た OOF に閾値を合わせ込んだ**。H8b は平均通り(+0.003)で歪みなし。
`fold内閾値std` も baseline 0.073 → H8 0.111 と悪化しており、テキスト追加で確率分布が
変わって閾値が不安定化している。→ **次の課題は特徴追加ではなく閾値とseedの分散低減**。

#### 健全性チェック
- train/test のテキスト分布は一致: 文字数 852±115 vs 848±110、キーワード出現率も同水準
- **train/test の重複行ゼロ**（コピーによるリークなし）、欠損ゼロ

#### 合成器

`logit(p_k)` を**非負**重み `w_k` で線形結合し sigmoid で戻す。
`loss = 平均ロジスティック損失 + alpha*||w||^2, s.t. w_k >= 0`

- 非負制約: 742行だと「あるエキスパートを逆張りで使う」符号反転が起きる。制約すれば
  効かない構成員は重み0に落ちるだけで済む
- 山登り/Optuna での OOF 直接最適化は**使わない**（自由度が高すぎてOOFに貼り付く）
- rank平均ではなく logit 平均。F1で閾値を切る以上、確率の絶対値情報を捨てるべきでない

### exp024 — 閾値則の比較 → 現行 oof_best 据え置き

- **実行**: `python exp/holdout_check.py --n-reps 5 --threshold-rules oof_best fold_mean rate half_f1`
- **日付**: 2026-08-10

「改善アイデア」の最優先項目だった「閾値の決め方」に決着を付けた。
4則すべて **A の情報だけ**で閾値を決める（rate は B のスコア分布のみ使用、ラベルは見ない）:

| 則 | 中身 | 自由度 |
|---|---|---|
| `oof_best` | A全体のOOFでF1最大（現行） | argmax1点＝過学習しやすい |
| `fold_mean` | A内5foldの最適閾値の平均 | 平均化で分散を落とす |
| `rate` | Aの予測正例率をBのスコア分位点に転写 | 閾値の絶対値に依存しない |
| `half_f1` | 達成F1の半分（校正済み確率でのF1最適値） | 最小 |

**F1 × 閾値則（exp019構成, B=259行×5rep, rep平均）**

| モデル | oof_best | fold_mean | rate | half_f1 |
|---|---|---|---|---|
| **meta_6本** | **0.7555** | 0.7487 | 0.7473 | 0.7485 |
| meta_4本 | 0.7448 | 0.7516 | 0.7463 | 0.7484 |
| uniform_6本 | 0.7497 | 0.7475 | 0.7489 | 0.6776 |
| E0単体 | 0.7155 | 0.7192 | 0.7095 | 0.7267 |

現本命に対する差分は `fold_mean` -0.0069 (1/5) / `rate` -0.0082 (1/5) / `half_f1` -0.0070 (0/5)。
**4×4のグリッド全体の最良が現行の meta_6本 × oof_best だった。**

**exp020 の救済可否**（meta_4本 − meta_6本）: `fold_mean` で -0.0107(0/5) → +0.0030(3/5) と
負けは消えるがコイン投げ。**「閾値さえ当てられれば4本構成が活きる」は成立しない。**

**重要な注意**: H21構成（exp023）で回すと `rate` が oof_best に **+0.0126 (4/5)** で勝つ。
exp019構成では -0.0082 (1/5) だったので、**2構成合計 5/10 ＝ 信号なし**。
5repだと片方のランだけ見て逆の結論に飛べてしまう。閾値則の判定は必ず両構成で見ること。

**残った穴**: `half_f1` は校正を動機にした則であって、isotonic/Platt で実際に校正してから
閾値を切る形は未検証。ただし `uniform_6本`（未校正）で -0.0773 (0/5) と壊滅する一方
`meta_6本` では -0.0070 に収まるので、メタ出力は既にそこそこ校正されており伸びしろは薄いと見る。

### exp025 — H22 アンケートのドメイン派生特徴をE2に追加 → REJECT

- **スクリプト**: `exp/survey_features.py`（特徴生成） / `exp/compare_survey.py`（E2単体の変種比較）
- **実行**: `python exp/ensemble_experts.py --seed 42 --survey-step`,
  `python exp/holdout_check.py --n-reps 5 --survey-step`
- **日付**: 2026-08-10

#### 動機 — なぜ財務(E1)ではなくアンケート(E2)を狙ったか

exp023 で財務比が「E1単体はACCEPT(明確)なのに合成で落ちる」形で死んだ直後だったので、
**改善の伝達率が高いエキスパート**を選び直した。

| | E1 財務 | E3 DX展望 | **E2 アンケート** |
|---|---|---|---|
| 合成重み(holdout) | 17.2% | 5.5% | **32.8%（最大）** |
| E0との相関 | 0.653 | 0.640 | **0.187** |
| モデル | LightGBM | LR | **LR** |

E2 は重みが最大で、E0(94列)との相関が 0.187 しかない＝単一モデルが取りこぼしている
領域を担当している。しかも診断で **LR が LGBM に AP +0.048 で明確勝ち**しており
（742行では木が1〜5の順序尺度11本を刻みすぎる）、
**このグループの非線形性は手で列にして LR に渡すしかない**という構図だった。
さらにエキスパートを増やさないので却下則3（構成員追加の重み推定ノイズ）のコストが無い。

#### 候補設計 — LRが原理的に作れないものだけ

差分 `a1 - a2` や重み付き和は LR が自前で作れる（`w1*a1 + w2*a2` と同型）ので、
**「ギャップ特徴」として差を足すのは無意味**。作れないのは次の4種類だけなので、
ここから3群を作った（列の定義は `survey_features.py`）。

| 群 | 内容 | 例 |
|---|---|---|
| shape | 行内の順序統計量 | 9項目のstd / レンジ / 中庸数 / 中央偏差和 |
| step | 閾値指標（線形項と併用で折れ線になる） | `a1>=4`, `a2<=2`, `a4>=4`, `a10>=4` |
| gap | 積（条件付き効果） | `a2*a8`, `a11*a10`, `a1*a10`, ツール不満(a6/a7統合) |

別途 `a7中央値埋め`（`harness.ZERO_FILL` の0埋めを外側train内の観測中央値に置換）も比較した。
`アンケート７` は48%欠損（`アンケート６`＝いいえと完全一致）かつ単体最強（購入率 1:0.464 → 5:0.127）
なので、0と1〜5の二峰分布が標準化のσを膨らませて最強項目をL2で過剰に縮めている疑いがあった。

#### 結果1: E2単体の20seedペア比較（`compare_survey.py`）

| 変種 | 列数 | ΔAP | ΔAUC | ΔF1 | 判定 |
|---|---|---|---|---|---|
| **step** | 12→16 | **+0.0151 (20/20)** | **+0.0099 (20/20)** | +0.0110 (19/20) | **ACCEPT (明確)** |
| all | 12→24 | +0.0020 (12/20) | +0.0039 (15/20) | +0.0075 (16/20) | PARK |
| shape | 12→16 | -0.0001 (7/20) | -0.0004 (10/20) | +0.0047 (15/20) | REJECT (ノイズ) |
| a7中央値埋め | 12 | +0.0002 (11/20) | +0.0004 (19/20) | +0.0005 (9/20) | PARK（step比では 16/20 だがノイズ） |
| **gap** | 12→16 | **-0.0094 (0/20)** | -0.0060 (0/20) | -0.0034 (3/20) | **REJECT (ガードレール違反)** |

- step の4本は drop-one でも `明確高`(ΔAP -0.0078, 0/20) と `満足低`(-0.0056, 0/20) が
  AP を、`抵抗高` が AUC/F1 を担っている。`連携高` だけ単独では死んでいるが、
  外すと AP -0.0017 / F1 -0.0036 と僅かに悪化するので4本のまま採った。
- a7中央値埋めは step 併用でも ΔAP +0.0006 (16/20) と効果なし。**0埋めのままでよい**
  （欠損行は isna フラグで独自の切片を持てるので表現力は落ちていなかった）。

#### 結果2: 合成後（seed42 OOF）— ここで逆転する

| | AUC | AP | F1 | th |
|---|---|---|---|---|

現行構成の再現性は確認済み（対E0 ΔF1 **+0.0400 正5/5** ＝ exp018/019 の記録値と一致）。
E0 は step列を含まないので両ランで完全一致し、rep 単位でペアが取れる。

| 指標 | 現行 meta_6本 | +step meta_6本 | **ペア差分（+step − 現行）** |
|---|---|---|---|

#### 機構 — 単体の改善を「直交性」で買っていた

step を入れた E2 の OOF 予測は、他エキスパートとの相関が**全面的に上昇**した
（E2以外のエキスパートは両ランで完全一致なので、これは純粋な E2 の差し替え効果）:

```
相手           r(E2現行,他)  r(E2+step,他)   変化
E0_anchor         0.187        0.213      +0.026
E6_manual        -0.009        0.033      +0.042
E3_dx_text        0.027        0.056      +0.029
E1_finance       -0.009        0.002      +0.011
```

メタもそれを検知して **E2の重みを 32.8% → 29.1% に下げた**（E0 が 25.3% → 28.9% に上昇）。

**なぜそうなるか**: step の4本は `a1`,`a2`,`a4`,`a10` を閾値で切った列であり、
これらの生値は E0 の94列に既に入っていて **E0 の木は同じ閾値分割を自分で作れる**。
つまり step は「E2 に E0 の担当分を再学習させる」変更だった。
E2 の合成価値は単体性能ではなく**他と無相関であること**から来ていた（単体最弱クラスの
AP 0.4283 なのに重み最大を取っていた）ので、直交性を売って単体APを買う取引は損になる。

#### 判定と残したもの

- **REJECT**。既定は現行のまま（`e2_survey_cols(with_step=False)`）で exp019 を完全再現する。
- コードは `--survey-step` フラグで残す（`finance_ratio_features` と同じ扱い）。
- exp020(4本構成) / exp023(財務比) に続き **3例目の「単体ACCEPT → 合成REJECT」**。
  却下則に昇格させた（下記）。

#### 副産物 — 単体APは事前スクリーニングとして機能しなかった

H21 の手順に倣って全候補の単体AP倍率と既存12列との最大|r|を先に測った（`survey_feature_report`）。
結果は**ランキングが逆**だった:

| 群 | 単体AP倍率 | 既存との最大\|r\| | 実測（E2単体20seed） |
|---|---|---|---|
| gap | **1.14〜1.31（最上位）** | 0.66〜0.70 | **0/20 で悪化** |
| step | 1.04〜1.15 | 0.86〜0.88（最悪） | **20/20 で ACCEPT** |
| shape | 1.06〜1.15 | **0.05〜0.12（最良）** | ノイズ |

- 積(gap)は定義上、単体APが高くても**線形項との重複で新規情報がない**ことがある。
- 閾値指標(step)は生値と|r|=0.87 だが、**線形空間に無い成分**（折れ線）を持つので効いた。
- 相関の低さ(shape)は却下則1のとおり採用根拠にならなかった。
- **教訓**: LRに足す列の足切りに「単体AP」「既存列との相関」は使えない。
  木(E1)向けの H21 の手順をそのまま流用したのが誤りで、判定は
  **モデルごと回す同一seedペア比較でしか付かない**。幸い E2 は LR なので20seedが数秒で回る。

### 方法論の注記 — OOF誤り分析による分析者リーク（2026-08-10）

0.8到達の道筋を探る過程で、**742行すべてのOOF誤りの中身を見た**。
業界別の誤り分布や「確信FP 32行」の特徴を掘る方向に進みかけたが、これは
**モデル選択のリーク**にあたる（ユーザー指摘により中止）。

- モデル学習のリークではない（どの行も自分のラベルを見ずに予測されている）
- **しかし742行のラベルを使って特徴設計を誘導すれば、その後に同じ742行で測るOOFは楽観側に出る**。
  自由度がモデルから分析者に移動するだけで、exp017 で焼かれたのと失敗の型は同じ

**破棄した観察**: 業界別の誤り分布（n=32 を31カテゴリに割ると最大7件＝ノイズ）、
確信FP 32行の個別特徴。

**残した観察**（行の同一性を含まない、ランキング関数の性質なので比較的安全）:
PR曲線上で**どの閾値を選んでも F1 は 0.76〜0.78 で頭打ち**。

→ **0.80には閾値調整では届かない。順位付けそのものの改善（＝新しい信号）が要る**。

**今後のルール**: 誤りの中身から出した仮説を採用する場合は、
`holdout_check.py` の構造を使い **A の中だけで誤りを見て B で検証する**。
ただし2026-08-10時点で742行全部の誤りを見てしまっているため、
**厳密に清潔な部分はもう残っていない**。以降の判断ではこの事実を割り引くこと。

### exp027 — H24 E2のモデル族を替える（木でも線形でもない非線形）→ REJECT

- **スクリプト**: `exp/compare_survey_kernel.py`
- **実行**: `python3 exp/compare_survey_kernel.py --n-seeds 5`
- **日付**: 2026-08-11

#### 動機

現行6本は LGBM×3 + LR×3 で、仮説空間が「軸平行の階段関数」と「超平面」しかない。
**滑らかで軸に平行でない決定境界**をどの構成員も表現していない。E2 を狙ったのは
(a) 同じ12列で LGBM 0.6446 < LR 0.6806 と**木が実際に負けている** (b) E0(94列)との
相関が 0.187 しかない (c) 合成重みが常に最大(38〜42%)、の3つが揃っていたため。

exp025(H22) が落ちたのは「閾値で切った列＝木が自分で作れる形」を足したからで、
モデル族の差し替えは失敗の型が違う、というのが賭けだった。

#### 事前登録した停止条件

**候補のOOFが M0_lr と Spearman 0.90 以上なら、単体スコアに関わらず却下。**
exp012(CatBoost, r=0.9495) と exp021(H9, r=0.927) が同じ形で落ちている。

#### 結果（5seed 同一seedペア比較）

| 変種 | AP | ΔAP (正/5) | ΔAUC (正/5) | vs M0_lr 相関 | 判定 |
|---|---|---|---|---|---|
| M0_lr（現行） | 0.4057 | — | — | — | — |
| M1_svm | 0.3834 | -0.0223 (0/5) | -0.0131 (0/5) | **0.9759** | REJECT |
| M2_gp（等方RBF） | 0.3828 | -0.0230 (0/5) | -0.0133 (0/5) | **0.9832** | REJECT |
| M3_gp_ard | 0.3778 | -0.0280 (0/5) | -0.0179 (0/5) | **0.9158** | REJECT |

**結論: この12列ではどのモデル族も同じ順位に収束し、その中で LR が最良。**

#### なぜそうなるか（等方GPが出した積極的な証拠）

GP が周辺尤度から選んだ `length_scale` は 11.2〜12.5。一方で標準化後の点間距離は
**中央値 4.88 / 最大 8.06**。つまりカーネル値はデータ全域で 0.78〜1.0 しか動かず、
RBF が `1 - d²/2ℓ²` の**線形領域で動作している**。探索上限(1e2)への張り付きではなく、
周辺尤度が自分でその解を選んでいる点が重要（＝調整不足ではない）。

ARD で列ごとに長さを学習させると アンケート４/７/１０/６ が 2.0〜4.2、
アンケート３/５/９/１１ が 681〜1000（実質オフ）に分離し、局所構造があるように
見えたが、それでも r=0.916 / ΔAP -0.0280 (0/5) で LR に届かなかった。

#### 副産物: 低い相関はバグの兆候でありうる

初回の M1_svm は `class_weight` 未指定で、正例率24%のまま hinge 損失を最小化した
結果 **OOF AUC 0.5546** まで落ちていた。このとき **M0_lr との相関は 0.614** で、
相関ゲートだけ見れば「多様性あり」に見えた。`class_weight="balanced"` に直すと
AUC 0.6547 に回復すると同時に**相関が 0.9759 に跳ね上がった**。

**教訓: 相関ゲートは単体スコアと必ず並べて読むこと。** 単体が弱いのに相関も低い
候補は、多様性ではなく壊れている可能性を先に疑う。

## 再現性の修正（2026-08-10）

`text_features.py:LR_PARAMS` と `organization_features.py:ORG_LR_PARAMS` の
`LogisticRegression(solver="liblinear", dual=True)` に **`random_state=0` を追加**した。

**症状**: コードを1文字も変えずに `make_submission_h1_h8.py --org-chart
--dx-outlook-manual --overview-six-rate-flags` を再実行すると、
OOF F1 が `0.7273 → 0.7349`、提出ラベルが2行変わった（id 844 が消え 1239 が増える）。

**原因**: liblinear の dual 座標降下法は座標の巡回順をランダムシャッフルする。
`random_state=None` だと sklearn が毎回ランダムな種を引くため、同一入力でも
確率が `1e-6` オーダーで揺れる。LightGBM 側は同一入力で完全一致することを検証済みで、
揺れの発生源はLRだけだった。

**なぜ 1e-6 が効くか**: このスコア `DX展望_購入確率` は下流LightGBMで gain 単独首位
（1390 ＝ 2位の2.3倍）。微差が分割点 → OOF閾値 → 境界行のラベル、と増幅される。

**重要**: この実行ごとのジッタ（2行）は、exp013→exp017 の Public差 +0.0254 の実体
（TP 48→50 の2行）と**同じ大きさ**だった。再現性を確保しないと、どの比較実験もΔが再現しない。

**副作用**: 修正前に記録した OOF 値は再実行時に微妙にズレる。修正前の記録は
そのまま残してあるので、修正後の値と直接比較しないこと。

**Public確定済みの提出ファイルは再生成しないこと**（`.git` は空ディレクトリでバージョン
管理されていない）。exp013 / exp017 の提出物は上書き事故を起こしたことがあり、
差分記録から復元した経緯がある。

## メモ

- Public評価は全体の30% = **240行のみ** → CV（OOF）スコアを優先すること
- **Public差を見たら必ず「何行分か」に換算する**（exp017で確立、exp019で改良）:
  1. スコアを分数化する（`Fraction(s).limit_denominator(2000)`）。F1は有理数なので必ず割り切れる
  2. `F1 = 2TP/(予測正例+実正例)` に当てはめ、`予測正例+実正例` が分母の整数倍になる
     候補を列挙する
  3. **提出が2件以上あるなら1件ずつ解かず、全件同時に最尤で解く**。公開集合Sは全提出で
     同一なので、提出間のラベル差分（`0→1` / `1→0` の件数）から「差分行のうち公開に
     落ちた数」の分布が作れて、スケールが一意に決まる。1件ずつだと候補が拮抗して外す
     （exp019 は単独だと 130 対 143 が z=1.80 対 1.86 で、実際に間違えかけた）
  4. 復元の妥当性は **OOF の適合率・再現率と突き合わせて**確認する
  5. TPの差が実体。**数行なら差はノイズ**。数十行動いて初めて信号を疑う
  - 併せて提出ファイル間のラベル差分件数も必ず数える（`0→1` / `1→0` の内訳まで）
- **Public F1 の標準偏差は実測 0.043**（240行、68%区間 ±0.04）。2026-08-10 時点の
  Public 5件（0.7559 / 0.7619 / 0.7692 / 0.78125 / 0.78195）は**全体が1σに収まらず、順位付け不能**
- **出現率が数%以下のフラグは LightGBM に届かない**（exp016 の `DX` 1.35% / `IoT` 0.81%、
  exp022 の `技研` 2.6% は、いずれも分割に一度も使われず予測が完全一致した）。
  少数キーワードをbinary特徴にするのは、このデータでは原理的に無駄
- **AUC/AP が上がっても F1 が上がるとは限らない**。exp020 は AUC/AP がOOF・ホールドアウト
  両方で微増したのに、ホールドアウトのF1は 0/5 で負けた（順位付けは同等以上なのに
  閾値を当てられていない）。**評価指標はF1なので、AP改善だけで採用しない**
- **OOF は閾値の当てやすさを過小評価する**。同一データ上の分割違いなので、
  ΔAPが+0.0005程度の僅差判断は、完全ホールドアウトでF1ガードレールを確認するまで信用しない
- **相関が低い＝直交した信号がある、ではない**。信号が無いものは何とも相関しない。
  直交性を採用根拠にする前に、単体APが正例率(0.241)をどれだけ上回るか必ず見ること
  （E2は0.43＝1.8倍で当たり、企業名は0.27でハズレ、exp026の意味的乖離は0.31でハズレ）
- **テキスト埋め込みが効くのは「TF-IDFが弱かった列」**（exp026）。極性語が直接効く長文
  （DX展望852文字）は char n-gram で取り切れていて相関0.934＝置換の価値なし。
  効いたのは語彙一致が使えない短い列（組織図の部署名羅列 r=0.560、企業概要 r=0.776）。
  **既にスコアが高い列を埋め込みで置き換えても伸びない**、が経験則
- **候補を採用する前に既存メンバーとの相関を必ず見る**。exp021(0.927)は却下、
  exp026の組織図(0.560)は採用。0.9超えは「同じ情報の別表現」で、合成は動かない
- **Public差 0.03未満は判断に使ってはいけない**（240行しかない。H8/H8bで2回焼かれている）
- 単seedのOOF差も同様に判断に使わない。ACCEPT/REJECTは `harness.py` の10seedペア比較で出す
- 最終提出は2ファイルまで選択可能。**Privateスコアの高い方が自動採用**されるため、
  「CV最良」＋「Public最良」を並べるヘッジは無コスト
- プレゼン審査があるため特徴量重要度・解釈性も記録しておく
